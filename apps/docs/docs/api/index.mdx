# REST API reference

NextBase serves a REST API under the route you mount it at, by default
`/api/nextbase`. Requests and responses are JSON. Every path in this reference is relative to that.

| Area | Paths |
| ---- | ----- |
| [Records](/docs/api/records) | `/collections/{collection}/records` |
| [Auth](/docs/api/auth) | `/collections/{collection}/auth-with-password`, `/session`, `/sessions` |
| [Realtime](/docs/api/realtime) | `/realtime` |
| [Collections](/docs/api/collections) | `/collections` (superusers) |
| [Setup and health](/docs/api/setup) | `/setup`, `/health` |

## Authentication

Send the session token from [signing in](/docs/api/auth#sign-in-with-a-password)
in the `Authorization` header (a "Bearer token"):

```http
Authorization: Bearer <token>
```

or sign in with a [session cookie](/docs/guides/auth/sessions), which the
browser sends on its own. If both are present, the header wins.

- An invalid or expired Bearer token is a `401`.
- An invalid cookie is removed and the request continues signed out.
- A response to a request that had no session carries
  `NextBase-Session: none`, so a browser that thought it was signed in with a
  cookie, which scripts cannot read, learns that its session ended.
- A write (`POST`, `PATCH`, `DELETE`) authenticated by the cookie must send an
  `Origin` header naming the same host, or it gets a `403`. Browsers do this
  on their own.

## Requests

Request bodies are JSON (`Content-Type: application/json`), up to 1 MiB.

## Errors

Every error has the same shape:

```json
{
  "status": 400,
  "message": "Failed to create the record.",
  "data": {
    "title": { "code": "validation_required", "message": "Cannot be blank." }
  }
}
```

`data` holds field errors, keyed by field and nested for nested input. `code`
is stable and meant for programs; `message` is for people.

| Status | Meaning |
| ------ | ------- |
| `400` | invalid input, a failed create rule, or a bad filter |
| `401` | missing or invalid credentials where they are required |
| `403` | signed in, but the action needs a superuser or another collection's session, or a cross-site cookie write |
| `404` | not found, or hidden by a rule |
| `405` | method not allowed |
| `409` | conflict with a concurrent change; retrying works |
| `413` | request body too large |
| `415` | request body is not JSON |
| `429` | over a rate limit, too many failed sign-in attempts, or too many realtime streams; see below |
| `500` | unexpected server error, logged on the server |

### Too many requests

Over a [rate limit](/docs/guides/rate-limits), the message is
`Too many requests.` and the response says when to retry and which rule
refused it:

```http
Retry-After: 2
RateLimit-Policy: "*:auth";q=2;w=3
RateLimit: "*:auth";r=0;t=2
```

`Retry-After` and `t` are the seconds until the window ends, and `q` the
requests the rule allows per window of `w` seconds. A `429` also answers too
many failed sign-ins to one account, `Too many attempts. Try again later.`
with `Retry-After` only, and a realtime stream past the 10 one account may
keep open.

### Field error codes

| Code | Meaning |
| ---- | ------- |
| `validation_required` | the value is empty |
| `validation_invalid_value` | the value is not allowed |
| `validation_invalid_type` | the value has the wrong type |
| `validation_invalid_format` | the value does not match the pattern |
| `validation_invalid_email`, `validation_invalid_url` | not an email or URL |
| `validation_domain_not_allowed` | the email or URL domain is not allowed |
| `validation_length_out_of_range` | text too short or too long |
| `validation_out_of_range` | number or date out of range |
| `validation_not_integer` | the number must be whole |
| `validation_too_many` | too many values selected |
| `validation_too_large` | JSON value too large |
| `validation_not_unique` | the value is already taken |
| `validation_missing_relation` | a related record does not exist |
| `validation_values_mismatch` | `passwordConfirm` differs from `password` |
| `validation_invalid_old_password` | `oldPassword` is missing or wrong |
| `validation_forbidden` | only superusers may change this field |
| `validation_invalid_rule` | a rule does not compile |
