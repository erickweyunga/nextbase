# Auth

Sign up and sign in to an [auth collection](/docs/guides/auth), and manage
sessions.

## Sign up

Creates an account, checked by the `createRule` like any
[create](/docs/api/records#create-a-record), then signs it in when the
`authRule` lets it.

```ts
await nb.collection("users").signUp({
  email: "ann@example.com",
  password: "a long password",
  passwordConfirm: "a long password",
});
```

```http
POST /collections/{collection}/sign-up
```

**Body:** the record's fields, as for a create, and `cookie: true` to keep
the session in a cookie, as when [signing in with a
password](#sign-in-with-a-password).

**Query parameters:** `expand` and `fields`, applied to `record`.

**Responses**

<Tabs>
<TabItem value="200" label="200">

The session, as when [signing in with a password](#sign-in-with-a-password).

</TabItem>
<TabItem value="202" label="202">

No body: the account was created, but the `authRule` does not let it sign in
yet, such as before its email is verified. The SDK returns `null`.

</TabItem>
<TabItem value="400" label="400">

Field errors, as for a [create](/docs/api/records#create-a-record).

</TabItem>
</Tabs>

## Sign in with a password

Checks the password and the collection's `authRule`, then starts a session.
Every failure returns the same error, so responses never reveal which emails
exist. Ten failures for one account within 15 minutes block it for the rest
of that window.

<Tabs groupId="client">
<TabItem value="sdk" label="SDK">

```ts
// Bearer token, kept by the SDK's auth store:
await nb.collection("users").signInWithPassword("ann@example.com", "a long password");

// Or an HttpOnly session cookie:
await nb.collection("users").signInWithPassword("ann@example.com", "a long password", {
  cookie: true,
});
```

</TabItem>
<TabItem value="curl" label="curl">

```sh
curl -X POST https://app.example/api/nextbase/collections/users/auth-with-password \
  -H 'content-type: application/json' \
  -d '{"identity":"ann@example.com","password":"a long password"}'
```

</TabItem>
</Tabs>

```http
POST /collections/{collection}/auth-with-password
```

**Body**

| Param | Type | Description |
| ----- | ---- | ----------- |
| `identity` | string | Required. The email (matched regardless of case), or another identity field. |
| `password` | string | Required. |
| `cookie` | boolean | Optional. `true` sets the session cookie instead of returning the token. The request must then send an `Origin` header naming this site. |

**Query parameters:** `expand` and `fields`, applied to `record`.

**Responses**

<Tabs>
<TabItem value="200" label="200">

```json
{
  "token": "yK2v0Xo8...43 characters",
  "record": {
    "collectionId": "c9d8e7f6a5b4c3d",
    "collectionName": "users",
    "id": "u7v8w9x0y1z2a3b",
    "email": "ann@example.com",
    "emailVisibility": false,
    "emailVerified": false,
    "phone": "",
    "phoneVerified": false,
    "name": "Ann"
  }
}
```
With `cookie: true`, `token` is left out and the response sets:

```http
Set-Cookie: __Host-nextbase_session=<token>; Path=/; Max-Age=604800; HttpOnly; SameSite=Lax; Secure
```

In development over plain HTTP, the cookie is `nextbase_session`, without
`Secure`.

</TabItem>
<TabItem value="400" label="400">

```json
{ "status": 400, "message": "Failed to authenticate.", "data": {} }
```

</TabItem>
<TabItem value="403" label="403">

```json
{ "status": 403, "message": "This account does not meet the requirements to sign in.", "data": {} }
```
The password matched, but the `authRule` did not.

</TabItem>
<TabItem value="429" label="429">

```json
{ "status": 429, "message": "Too many failed attempts. Try again later.", "data": {} }
```

</TabItem>
</Tabs>

## Sign in with OAuth2

Redirects the browser to an [OAuth2 provider](/docs/guides/auth/oauth2). The
provider sends it back to the callback below, which signs it in and redirects
to `redirect` on your app, or to `errorRedirect` with `?error=`. Open it as a
page, not with `fetch`.

<Tabs groupId="client">
<TabItem value="sdk" label="SDK">

```ts
nb.collection("users").signInWithOAuth2("google", { redirect: "/dashboard" });

// Or the URL, for a link:
const url = nb.collection("users").oauth2Url("google", { redirect: "/dashboard" });
```

</TabItem>
<TabItem value="html" label="HTML">

```html
<a href="/api/nextbase/collections/users/auth-with-oauth2/google?redirect=/dashboard">
  Continue with Google
</a>
```

</TabItem>
</Tabs>

```http
GET /collections/{collection}/auth-with-oauth2/{provider}
```

**Query parameters**

| Param | Type | Description |
| ----- | ---- | ----------- |
| `redirect` | string | Optional. A path on your app to return to, such as `/dashboard`. Defaults to `appUrl`. |
| `errorRedirect` | string | Optional. A path to return to with `?error=` when the sign-in fails, such as `/sign-in`. Defaults to `redirect`. |
| `link` | boolean | Optional. `true` links the provider to the signed-in record instead of signing in. Needs a session cookie, and must come from this site. |

**Responses**

<Tabs>
<TabItem value="302" label="302">

Redirects to the provider and sets a short-lived cookie that ties the sign-in
to this browser.

</TabItem>
<TabItem value="400" label="400">

```json
{ "status": 400, "message": "redirect must be a path on the app.", "data": { "redirect": { "code": "validation_invalid_redirect", "message": "Must be a path, such as /dashboard." } } }
```
Also returned for the superusers collection.

</TabItem>
<TabItem value="404" label="404">

```json
{ "status": 404, "message": "OAuth2 provider not found.", "data": {} }
```

</TabItem>
</Tabs>

## OAuth2 callback

Where providers send the browser back: register
`{appUrl}{basePath}/callback/{provider}` at each provider. It checks that the
browser returned from the provider the sign-in went to, then finishes the
sign-in, sets the session cookie and redirects to the sign-in's `redirect`,
or, when it fails, to its `errorRedirect` with `?error=` (see
[when a sign-in fails](/docs/guides/auth/oauth2#when-a-sign-in-fails)).

```http
GET /callback/{provider}
```

A provider that is not set up answers `404`, with no redirect.

Ends one of the signed-in record's sessions, such as a lost device. Revoking
the current cookie session also removes the cookie.

<Tabs groupId="client">
<TabItem value="sdk" label="SDK">

```ts
await nb.revokeSession("s1t2u3v4w5x6y7z");
```

</TabItem>
<TabItem value="curl" label="curl">

```sh
curl -X DELETE https://app.example/api/nextbase/sessions/s1t2u3v4w5x6y7z \
  -H 'authorization: Bearer <token>'
```

</TabItem>
</Tabs>

```http
DELETE /sessions/{id}
```

<Tabs>
<TabItem value="204" label="204">

No body.

</TabItem>


</TabItem>
<TabItem value="404" label="404">

```json
{ "status": 404, "message": "Session not found.", "data": {} }
```
Also returned for another record's session.
