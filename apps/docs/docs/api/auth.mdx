# Auth

Sign up and sign in to an [auth collection](/docs/guides/auth), and manage
sessions.

## Sign up

Creates an account, checked by the `createRule` like any
[create](/docs/api/records#create-a-record), then signs it in when the
`authRule` lets it.

```ts
await nb.collection("users").signUp({
  email: "ann@example.com",
  password: "a long password",
  passwordConfirm: "a long password",
});
```

```http
POST /collections/{collection}/sign-up
```

**Body:** the record's fields, as for a create, and `cookie: true` to keep
the session in a cookie, as when [signing in with a
password](#sign-in-with-a-password).

**Query parameters:** `expand` and `fields`, applied to `record`.

**Responses**

<Tabs>
<TabItem value="200" label="200">

The session, as when [signing in with a password](#sign-in-with-a-password).

</TabItem>
<TabItem value="202" label="202">

The account was created, but cannot sign in yet. Without a body, the
`authRule` does not let it, such as before its email is verified; the SDK
returns `null`. With `{ "mfa": "verify" }`, it must take a
[second step](#multi-factor-sign-in) and has none yet, such as a verified
email; the SDK returns that object.

</TabItem>
<TabItem value="400" label="400">

Field errors, as for a [create](/docs/api/records#create-a-record).

</TabItem>
</Tabs>

## List auth methods

The ways to sign in to the collection, for a login page.

```ts
const methods = await nb.collection("users").listAuthMethods();
```

```http
GET /collections/{collection}/auth-methods
```

**Response**

```json
{
  "password": { "enabled": true, "identityFields": ["email"] },
  "oauth2": { "enabled": true, "providers": [{ "name": "google", "displayName": "Google" }] },
  "phone": { "enabled": false },
  "mfa": { "enabled": true, "duration": 300 }
}
```

`mfa` says whether some accounts may have to take a
[second sign-in step](/docs/guides/auth/mfa), and how many seconds it may take.

## Sign in with a password

Checks the password and the collection's `authRule`, then starts a session.
Every failure returns the same error, so responses never reveal which emails
exist. Ten failures for one account within 15 minutes block it for the rest
of that window.

<Tabs groupId="client">
<TabItem value="sdk" label="SDK">

```ts
// Bearer token, kept by the SDK's auth store:
await nb.collection("users").signInWithPassword("ann@example.com", "a long password");

// Or an HttpOnly session cookie:
await nb.collection("users").signInWithPassword("ann@example.com", "a long password", {
  cookie: true,
});
```

</TabItem>
<TabItem value="curl" label="curl">

```sh
curl -X POST https://app.example/api/nextbase/collections/users/auth-with-password \
  -H 'content-type: application/json' \
  -d '{"identity":"ann@example.com","password":"a long password"}'
```

</TabItem>
</Tabs>

```http
POST /collections/{collection}/auth-with-password
```

**Body**

| Param | Type | Description |
| ----- | ---- | ----------- |
| `identity` | string | Required. The email (matched regardless of case), or another identity field. |
| `password` | string | Required. |
| `cookie` | boolean | Optional. `true` sets the session cookie instead of returning the token. The request must then send an `Origin` header naming this site. |
| `mfaId` | string | Optional. Makes the password the [second step](#multi-factor-sign-in) of this sign-in. |

**Query parameters:** `expand` and `fields`, applied to `record`.

**Responses**

<Tabs>
<TabItem value="200" label="200">

```json
{
  "token": "yK2v0Xo8...43 characters",
  "methods": ["password"],
  "record": {
    "collectionId": "c9d8e7f6a5b4c3d",
    "collectionName": "users",
    "id": "u7v8w9x0y1z2a3b",
    "email": "ann@example.com",
    "emailVisibility": false,
    "emailVerified": false,
    "phone": "",
    "phoneVerified": false,
    "name": "Ann"
  }
}
```
With `cookie: true`, `token` is left out and the response sets:

```http
Set-Cookie: __Host-nextbase_session=<token>; Path=/; Max-Age=604800; HttpOnly; SameSite=Lax; Secure
```

In development over plain HTTP, the cookie is `nextbase_session`, without
`Secure`.

</TabItem>
<TabItem value="400" label="400">

```json
{ "status": 400, "message": "Failed to authenticate.", "data": {} }
```

</TabItem>
<TabItem value="403" label="403">

```json
{ "status": 403, "message": "This account does not meet the requirements to sign in.", "data": {} }
```
The password matched, but the `authRule` did not.

</TabItem>
<TabItem value="401" label="401">

```json
{ "status": 401, "message": "This sign-in needs a second step.", "data": {}, "mfaId": "kQ9...43 characters", "methods": ["totp", "recoveryCode"] }
```
The password matched, and the account must take a
[second step](#multi-factor-sign-in). No session started.

</TabItem>
<TabItem value="429" label="429">

```json
{ "status": 429, "message": "Too many failed attempts. Try again later.", "data": {} }
```

</TabItem>
</Tabs>

## Sign in with OAuth2

Redirects the browser to an [OAuth2 provider](/docs/guides/auth/oauth2). The
provider sends it back to the callback below, which signs it in and redirects
to `redirect` on your app, or to `errorRedirect` with `?error=`. Open it as a
page, not with `fetch`.

<Tabs groupId="client">
<TabItem value="sdk" label="SDK">

```ts
nb.collection("users").signInWithOAuth2("google", { redirect: "/dashboard" });

// Or the URL, for a link:
const url = nb.collection("users").oauth2Url("google", { redirect: "/dashboard" });
```

</TabItem>
<TabItem value="html" label="HTML">

```html
<a href="/api/nextbase/collections/users/auth-with-oauth2/google?redirect=/dashboard">
  Continue with Google
</a>
```

</TabItem>
</Tabs>

```http
GET /collections/{collection}/auth-with-oauth2/{provider}
```

**Query parameters**

| Param | Type | Description |
| ----- | ---- | ----------- |
| `redirect` | string | Optional. A path on your app to return to, such as `/dashboard`. Defaults to `appUrl`. |
| `errorRedirect` | string | Optional. A path to return to with `?error=` when the sign-in fails, such as `/sign-in`. Defaults to `redirect`. |
| `mfaId` | string | Optional. Makes this the [second step](#multi-factor-sign-in) of a sign-in: the provider account must already be linked to the account signing in. Nothing is linked or signed up. |
| `params` | string | Optional. A JSON object of strings for the provider's page, such as `{"login_hint":"ann@example.com"}`, over the provider's own `params`. Those NextBase sets itself answer `400`. |
| `data` | string | Optional. A JSON object, at most 2 KB, passed to the provider's `mapProfile` when the sign-in creates an account. |

**Responses**

<Tabs>
<TabItem value="302" label="302">

Redirects to the provider and sets a short-lived cookie that ties the sign-in
to this browser.

</TabItem>
<TabItem value="400" label="400">

```json
{ "status": 400, "message": "redirect must be a path on the app.", "data": { "redirect": { "code": "validation_invalid_redirect", "message": "Must be a path, such as /dashboard." } } }
```
Also returned for the superusers collection.

</TabItem>
<TabItem value="404" label="404">

```json
{ "status": 404, "message": "OAuth2 provider not found.", "data": {} }
```

</TabItem>
</Tabs>

## Sign in with an ID token

Signs in with an ID token a native app got from the provider's SDK. See
[Native apps](/docs/guides/auth/oauth2#native-apps).

```ts
await nb.collection("users").signInWithIdToken("google", idToken, { nonce });
```

```http
POST /collections/{collection}/auth-with-id-token/{provider}
```

| Param | Type | Description |
| ----- | ---- | ----------- |
| `token` | string | Required. The ID token. |
| `nonce` | string | Optional. The nonce given to the SDK; the token must carry it, or its SHA-256 hex. |
| `data` | object | Optional. Passed to the provider's `mapProfile` when the sign-in creates an account. |
| `cookie` | boolean | Optional. Puts the session in a cookie instead of the response. |
| `mfaId` | string | Optional. Makes this the second step of a sign-in. |

Answers like [Sign in with a password](#sign-in-with-a-password). An
invalid, expired, foreign or used token answers `400` with
`data.token.code` `validation_invalid_token`; the browser sign-in's errors,
such as `email_not_verified` or `sign_up_disabled`, answer `400` with that
code in `data.token.code`.

## OAuth2 callback

Where providers send the browser back: register
`{appUrl}{basePath}/callback/{provider}` at each provider. It checks that the
browser returned from the provider the sign-in went to, then finishes the
sign-in, sets the session cookie and redirects to the sign-in's `redirect`,
or, when it fails, to its `errorRedirect` with `?error=` (see
[when a sign-in fails](/docs/guides/auth/oauth2#when-a-sign-in-fails)).

```http
GET /callback/{provider}
```

A provider that is not set up answers `404`, with no redirect.

When the account must take a [second step](#multi-factor-sign-in), no session
starts: the callback sets an `HttpOnly` cookie, `__Host-nextbase_mfa`
(`nextbase_mfa` over plain HTTP), that lasts the collection's `mfa.duration`,
and redirects to `redirect` with `mfa=required` added to its query; the page
reads the methods with [`GET /collections/{collection}/mfa`](#the-methods-of-an-oauth2-sign-in).
A second step that fails returns to `errorRedirect` with
`?error=mfa_failed`.

## Link a provider

Starts linking a provider to the signed-in record, which needs a session
cookie, and answers the provider's URL to open in this browser. It needs the
current password, so a stolen session cannot add a way in, and must come
from this site.

```ts
await nb.collection("users").linkOAuth2("github", { password, redirect: "/settings" });
```

```http
POST /collections/{collection}/link-oauth2/{provider}
```

| Param | Type | Description |
| ----- | ---- | ----------- |
| `password` | string | Required. The current password. |
| `mfaCode` | string | Required once the account has an [authenticator app](/docs/guides/auth/mfa): a code from it, or a recovery code. |
| `redirect` | string | Optional. A path on your app to return to. |
| `errorRedirect` | string | Optional. A path to return to with `?error=`. |
| `params` | object | Optional. Strings for the provider's page, as on sign-in. |

```json
{ "url": "https://github.com/login/oauth/authorize?..." }
```

It also sets the short-lived cookie that ties the link to this browser. The
callback then links the provider and returns to `redirect`.

## Approve an email change

Opens the link the current, verified address got: `newEmail` then gets its
link to confirm. The token works once, for the address it was made for, and
expires with the collection's `emailChange` token duration. Answers `204`.

```ts
await nb.collection("users").approveEmailChange(token);
```

```http
POST /collections/{collection}/approve-email-change
```

| Param | Type | Description |
| ----- | ---- | ----------- |
| `token` | string | Required. From the link. |
| `newEmail` | string | Optional. When set, it must be the address the link names. |

An invalid, used or expired token answers `400` with `data.token.code`
`validation_invalid_token`. A verified account's change cannot be confirmed
without this approval.

## Request an account deletion

Emails the signed-in account a link that deletes it, to
`/delete-account?token=...` in your app, for an owner who can confirm neither
with a password nor a recent sign-in. See
[Account deletion](/docs/guides/auth/account-deletion). Answers `204`.

```ts
await nb.collection("users").requestAccountDeletion();
```

```http
POST /collections/{collection}/request-account-deletion
```

Needs a signed-in session of an account with a verified email; otherwise
`401` or `400`. A `deleteRule` of `null`, or an
[impersonation](/docs/guides/auth/impersonation) session, answers `403`.

## Confirm an account deletion

Deletes the account the link was sent for, as its owner: the collection's
`deleteRule` still decides. Answers `204`.

```ts
await nb.collection("users").confirmAccountDeletion(token);
```

```http
POST /collections/{collection}/confirm-account-deletion
```

| Param | Type | Description |
| ----- | ---- | ----------- |
| `token` | string | Required. From the link. |
| `mfaCode` | string | Required once the account has an [authenticator app](/docs/guides/auth/mfa): a code from it, or a recovery code. |

## Multi-factor sign-in

A first step that must be followed by a second, such as a password for an
account with an authenticator app, answers `401` with an `mfaId` and the
`methods` the account can use next. No session starts. See the
[guide](/docs/guides/auth/mfa).

```json
{ "status": 401, "message": "This sign-in needs a second step.", "data": {}, "mfaId": "kQ9...43 characters", "methods": ["totp", "recoveryCode"] }
```

The second step is one of the routes below, or a first-step route given the
`mfaId`: `auth-with-password` and `auth-with-phone-code` in their body,
`request-phone-code` in its body, and `auth-with-oauth2/{provider}` as a query
parameter. It must be another method than the first, and once the account
has an authenticator app, `totp` or `recoveryCode`. It answers like a sign-in,
with `methods` naming both steps:

```json
{ "token": "yK2v0Xo8...43 characters", "methods": ["password", "totp"], "record": { "id": "u7v8w9x0y1z2a3b" } }
```

Without an `mfaId` in the body, the second-step routes use the
`__Host-nextbase_mfa` cookie an [OAuth2 first step](#oauth2-callback) set, and
answer with a session cookie; the request must then come from this site.
Every one takes `cookie: true` for a session cookie, and `expand` and `fields`
for `record`.

| Error | When |
| ----- | ---- |
| `400` with `data.mfaId.code` `validation_invalid_mfa` | The `mfaId` is unknown, used, expired, of another account or collection, or ended by a new password. |
| `400` with `data.mfaId.code` `validation_mfa_method` | This method cannot be the second step. |
| `400` with `data.code.code` `validation_invalid_code` | The code is wrong. The fifth wrong code ends the `mfaId`. |
| `429` | Ten wrong codes for the account within 15 minutes. |

### Sign in with an authenticator app

```ts
await nb.collection("users").signInWithTotp("123456", { mfaId });
```

```http
POST /collections/{collection}/auth-with-totp
```

| Param | Type | Description |
| ----- | ---- | ----------- |
| `code` | string | Required. Six digits. |
| `mfaId` | string | Optional; the cookie is used without it. |
| `cookie` | boolean | Optional. |

### Sign in with a recovery code

```ts
await nb.collection("users").signInWithRecoveryCode("7Q2M-K8WD-3HJX-TP9C", { mfaId });
```

```http
POST /collections/{collection}/auth-with-recovery-code
```

| Param | Type | Description |
| ----- | ---- | ----------- |
| `code` | string | Required. Case, spaces and dashes do not matter. Each works once, and the owner is emailed. |
| `mfaId` | string | Optional; the cookie is used without it. |
| `cookie` | boolean | Optional. |

### Request an email code

Emails a six-digit code to the account's verified email. Answers `204`.

```ts
await nb.collection("users").requestEmailCode({ mfaId });
```

```http
POST /collections/{collection}/request-email-code
```

| Param | Type | Description |
| ----- | ---- | ----------- |
| `mfaId` | string | Optional; the cookie is used without it. |

### Sign in with an email code

```ts
await nb.collection("users").signInWithEmailCode("123456", { mfaId });
```

```http
POST /collections/{collection}/auth-with-email-code
```

| Param | Type | Description |
| ----- | ---- | ----------- |
| `code` | string | Required. The latest code emailed. |
| `mfaId` | string | Optional; the cookie is used without it. |
| `cookie` | boolean | Optional. |

### A phone code as the second step

With phone sign-in on and a verified phone, `request-phone-code` and
`auth-with-phone-code` take an `mfaId` instead of a `phone`, and text the
account's own phone.

```ts
await nb.collection("users").requestMfaPhoneCode({ mfaId });
await nb.collection("users").signInWithMfaPhoneCode("123456", { mfaId });
```

### The methods of an OAuth2 sign-in

After an OAuth2 first step, the page reads the methods its pending sign-in
can take, with the `HttpOnly` cookie the callback set:

```ts
const { methods } = await nb.collection("users").getPendingMfa();
```

```http
GET /collections/{collection}/mfa
```

```json
{ "methods": ["totp", "recoveryCode"] }
```

Without the cookie, or once the sign-in ended, it answers `400` with
`data.mfaId.code` `validation_invalid_mfa`.

## Manage the authenticator app

Only the signed-in record itself, and never an impersonation session
(`403`). Another record is a `404`. A superuser can only
[clear](#clear-an-accounts-app) another record's app.

### Get the status

```http
GET /collections/{collection}/records/{id}/mfa
```

```json
{ "totp": true, "recoveryCodesLeft": 10 }
```

### Start setting up an app

```http
POST /collections/{collection}/records/{id}/totp
```

| Param | Type | Description |
| ----- | ---- | ----------- |
| `password` | string | Required. The current password. |

```json
{ "secret": "JBSWY3DPEHPK3PXPJBSWY3DPEHPK3PXP", "uri": "otpauth://totp/app.example:ann%40example.com?secret=JBSWY3DPEHPK3PXPJBSWY3DPEHPK3PXP&issuer=app.example&algorithm=SHA1&digits=6&period=30" }
```

`400` when `mfa.enabled` is off, without the `secretKey` option
(`data.secretKey.code` `secret_key_not_configured`), without a verified email
or phone (`data.totp.code` `validation_not_verified`), or when an app is set
up already. The setup must be confirmed within 15 minutes.

### Confirm the app

```http
POST /collections/{collection}/records/{id}/totp/confirm
```

| Param | Type | Description |
| ----- | ---- | ----------- |
| `code` | string | Required. A code from the app. |

```json
{ "recoveryCodes": ["7Q2M-K8WD-3HJX-TP9C", "...10 codes"] }
```

Every other session of the account ends; this one is kept, and its
`methods` gain `totp`. The owner is emailed.

### Remove the app

```http
DELETE /collections/{collection}/records/{id}/totp
```

| Param | Type | Description |
| ----- | ---- | ----------- |
| `mfaCode` | string | Required. A code from the app, or a recovery code. |

Answers `204`. Sessions are kept, the recovery codes are removed, and the
owner is emailed.

### Regenerate recovery codes

```http
POST /collections/{collection}/records/{id}/recovery-codes
```

| Param | Type | Description |
| ----- | ---- | ----------- |
| `mfaCode` | string | Required. A code from the app, or a recovery code. |

```json
{ "recoveryCodes": ["7Q2M-K8WD-3HJX-TP9C", "...10 codes"] }
```

Every old code stops working.

### Clear an account's app

Superusers only, and never through an impersonation session: removes another
record's app, recovery codes and pending sign-ins, for an owner who lost
them, and emails the owner. A superuser's own app is removed with a code
instead (`400`). Answers `204`, or `404` for no such record.

```ts
await nb.collection("users").clearMfa(userId);
```

```http
DELETE /collections/{collection}/records/{id}/mfa
```

## Impersonate

Superusers only. Starts a session that acts as a record of an auth
collection, as if its owner had signed in, without their password and
without checking the collection's `authRule`. The session lasts `duration`
seconds, is never extended, and cannot change how the account signs in. See
[Impersonation](/docs/guides/auth/impersonation).

<Tabs groupId="client">
<TabItem value="sdk" label="SDK">

```ts
// A new client acting as the record; nb stays signed in as the superuser:
const { client } = await nb.collection("users").impersonate("u7v8w9x0y1z2a3b");

// Or this browser's cookie session becomes the record's until nb.signOut():
await nb.collection("users").impersonate("u7v8w9x0y1z2a3b", { cookie: true });
```

</TabItem>
<TabItem value="curl" label="curl">

```sh
curl -X POST https://app.example/api/nextbase/collections/users/impersonate/u7v8w9x0y1z2a3b \
  -H 'authorization: Bearer <superuser token>' \
  -H 'content-type: application/json' \
  -d '{"duration":900}'
```

</TabItem>
</Tabs>

```http
POST /collections/{collection}/impersonate/{id}
```

**Body**

| Param | Type | Description |
| ----- | ---- | ----------- |
| `duration` | number | Optional. Whole seconds from `60` to `3600`. Defaults to `3600`. |
| `cookie` | boolean | Optional. `true` sets the session cookie instead of returning the token, and keeps the superuser's own cookie session aside in `__Host-nextbase_impersonator` until [sign out](#sign-out). The superuser must be signed in with the cookie, and the request must send an `Origin` header naming this site. |

**Query parameters:** `expand` and `fields`, applied to `record`, as the
record would see them.

**Responses**

<Tabs>
<TabItem value="200" label="200">

```json
{
  "token": "yK2v0Xo8...43 characters",
  "record": { "collectionName": "users", "id": "u7v8w9x0y1z2a3b", "email": "ann@example.com" },
  "session": {
    "id": "s1t2u3v4w5x6y7z",
    "created": "2026-10-19T09:30:00.000Z",
    "expires": "2026-10-19T10:30:00.000Z",
    "userAgent": "Mozilla/5.0 ...",
    "current": false,
    "impersonatedBy": "a1b2c3d4e5f6g7h"
  }
}
```
With `cookie: true`, `token` is left out and the response sets the session
cookie, as a [sign-in](#sign-in-with-a-password) does.

</TabItem>
<TabItem value="400" label="400">

```json
{
  "status": 400,
  "message": "Failed to impersonate.",
  "data": {
    "duration": {
      "code": "validation_invalid_value",
      "message": "Must be a whole number of seconds from 60 to 3600."
    }
  }
}
```
Also `Impersonation in cookie mode needs a cookie session.` for `cookie: true`
from a superuser signed in with a Bearer token, whose token the cookie would
replace.

</TabItem>
<TabItem value="401" label="401">

```json
{ "status": 401, "message": "Sign in as a superuser to do this.", "data": {} }
```

</TabItem>
<TabItem value="403" label="403">

```json
{ "status": 403, "message": "Only superusers can do this.", "data": {} }
```
Also `Superusers cannot be impersonated.` for `_superusers`, `Sign in as a
superuser to impersonate.` for server code using `client({ superuser: true })`,
which has no superuser to act for the record, and `Impersonation sessions
cannot impersonate.`

</TabItem>
<TabItem value="404" label="404">

```json
{ "status": 404, "message": "Record not found.", "data": {} }
```
Or `Collection not found.` when the collection does not exist or is not an
auth collection.

</TabItem>
</Tabs>
