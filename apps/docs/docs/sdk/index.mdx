# Client SDK

```ts
import { NextBaseClient, type RecordModel } from "@nextbasejs/client";

const nb = new NextBaseClient(); // baseUrl defaults to "/api/nextbase"
```

## Records

```ts
interface Post extends RecordModel {
  title: string;
  author: string;
}

const posts = nb.collection<Post>("posts");

const page = await posts.getList(1, 20, {
  filter: nb.filter("title ~ {:q} && created > {:since}", { q, since }),
  sort: "-created",
  expand: "author",
});
const all = await posts.getFullList({ sort: "title" });
const first = await posts.getFirstListItem(nb.filter("slug = {:slug}", { slug }));
const one = await posts.getOne(id, { fields: "id,title" });

await posts.create({ title: "Hello" });
await posts.update(id, { title: "Hello again" });
await posts.delete(id);
```

`create` and `update` return `null` when the write succeeded but the rules do
not let the caller view the result.

## Files

```ts
const url = nb.files.getUrl(post, post.cover);
const thumb = nb.files.getUrl(post, post.cover, { thumb: "100x100" });
const download = nb.files.getUrl(post, post.cover, { download: true });

// Protected files, where no session cookie is sent:
const token = await nb.files.getToken();
const secret = nb.files.getUrl(user, user.scan, { token, thumb: "64x64" });
```

`thumb` takes `100x100` or one of the field's `thumbs` sizes; for other
sizes and files that are not images, the URL redirects to the original. See
[Files](/docs/guides/files#thumbnails).

## Impersonation

Superusers only. Act as a user to see the app as they do:

```ts
const { client, record, session } = await nb
  .collection("users")
  .impersonate(userId, { duration: 900 });
await client.collection("posts").getList(); // as the user
await client.signOut(); // ends the impersonation early
```

`client` is a new client of the same server with an in-memory auth store, so
`nb` stays signed in as the superuser. With `{ cookie: true }`, which needs
`nb` signed in with the cookie, the browser's cookie session becomes the
user's instead, `nb.authStore` holds their record, and `nb.signOut()` puts
the superuser's own session and record back. See
[Impersonation](/docs/guides/auth/impersonation).

`nb.withAuthStore(store)` gives a client of the same server signed in through
another auth store.

## Multi-factor sign-in

A first step that needs a second throws a `401` that keeps the auth store;
`isMfaRequired(error)` reads it:

```ts
import { isMfaRequired } from "@nextbasejs/client";

const users = nb.collection("users");
try {
  await users.signInWithPassword(email, password);
} catch (error) {
  const mfa = isMfaRequired(error); // { mfaId, methods } or undefined
  if (!mfa) throw error;
  if (mfa.methods.includes("totp")) {
    await users.signInWithTotp(code, { mfaId: mfa.mfaId });
  } else if (mfa.methods.includes("emailCode")) {
    await users.requestEmailCode({ mfaId: mfa.mfaId });
    await users.signInWithEmailCode(emailedCode, { mfaId: mfa.mfaId });
  }
}
```

Second steps: `signInWithTotp`, `signInWithRecoveryCode`, `requestEmailCode`
with `signInWithEmailCode`, `requestMfaPhoneCode` with
`signInWithMfaPhoneCode`, and an `mfaId` option on `signInWithPassword` and
`signInWithOAuth2`. Without an `mfaId`, they use the cookie an OAuth2 sign-in
set, and `getPendingMfa()` reads its methods. The session's `methods`,
such as `["password", "totp"]`, come back in the response and in
`getSession()`.

The signed-in record manages its authenticator app:

```ts
const { totp, recoveryCodesLeft } = await users.getMfa(me.id);
const { secret, uri } = await users.startTotp(me.id, password);
const recoveryCodes = await users.confirmTotp(me.id, codeFromApp);
const fresh = await users.regenerateRecoveryCodes(me.id, codeFromApp);
await users.removeTotp(me.id, codeFromApp);
// As a superuser, for an owner who lost their app:
await users.clearMfa(userId);
```

Linking or unlinking a provider and changing the phone take
`{ password, mfaCode }`, and a verified email's inbox approves an email
change with `approveEmailChange(token)`. `signUp()` returns
`{ mfa: "verify" }` when the account must take a second step and has none
yet.

See [Multi-factor sign-in](/docs/guides/auth/mfa).

## Realtime

```ts
const unsubscribe = posts.subscribe(
  "*",
  ({ action, record }) => console.log(action, record.title),
  { filter: nb.filter("author = {:author}", { author }), expand: "author" },
);
const stopWatchingOne = posts.subscribe(id, ({ record }) => console.log(record));

unsubscribe();
stopWatchingOne();
```

`subscribe` takes `"*"` for every record the list rule allows, or a record id
for one record under the view rule, and returns the function that
unsubscribes. All subscriptions share one stream, which reconnects and resumes
on its own. Its `onReset` option is called once the subscription is live and
whenever events may have been missed: load what you show there. See
[Realtime](/docs/guides/realtime).

## Filters

Never put user input into a filter string yourself. `nb.filter()` replaces each
`{:name}` with a safely quoted value: strings and dates become quoted strings,
numbers stay numbers, and `null` or `undefined` become `null`.

## Errors

Every failure throws a `ClientError`:

```ts
import { ClientError } from "@nextbasejs/client";

try {
  await posts.create({});
} catch (error) {
  if (error instanceof ClientError) {
    error.status; // 400
    error.data; // { title: { code: "validation_required", message: "Cannot be blank." } }
  }
}
```

A request that never got a response (offline, or aborted) has `status` 0.
`error.isTimeout` is true when its `signal` timed out, as with
`AbortSignal.timeout()`, and `error.isAbort` when it was aborted for any other
reason, such as `controller.abort()`.

## Request options

Every method takes fetch options such as `signal`, `cache` and Next.js's
`next: { revalidate }`, plus `query` and `headers`. The server-side client
from `nextbase.client()` or `serverClient()` calls NextBase in-process, without
`fetch`, so `cache` and `next` do nothing there; `signal` works as with
`fetch`: an aborted request fails with a `ClientError` whose `isAbort` is true.

## Auth store

`nb.authStore` holds the signed-in record (and the token, for Bearer
sessions). In the browser it persists to `localStorage` and syncs across tabs.
Subscribe with `nb.authStore.onChange((token, record) => {})`. A 401 from the
server clears it, and so does a response saying the request had no session,
which is how a cookie session that ended elsewhere is noticed. A 403, such as
for a request that needs another collection's session, leaves it.

When requests overlap, the sign-in or sign-out started last wins, and
`getSession()` and `refreshSession()` leave the store as it is if it changed
while they were in flight.
