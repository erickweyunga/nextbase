# Passkeys

Users sign in with a passkey: a key their device keeps, unlocked with a
fingerprint, face or PIN, and often synced by their password manager. There
is no password to phish or leak, as a passkey only works on your site. It
needs the `appUrl` option of `new NextBase()`, whose host the passkeys are
bound to, and the collection's `passkeySignIn` option:

```ts
await superuser.collections.update("users", { passkeySignIn: true });
```

## Add a passkey

A signed-in user creates one on their device, in the browser:

```ts
const users = nb.collection("users");
await users.addPasskey(record.id, { name: "Laptop" });
```

It adds a way into the account, so a stolen session alone cannot add one: it
needs the `password`, unless the session signed in within the last day, and
with an [authenticator app](/docs/guides/auth/mfa) an `mfaCode` from it. The
owner is emailed. A good moment to offer it is right after another sign-in,
such as with a password or an [email code](/docs/guides/auth/email-code),
and after a sign-up.

## Sign in

```ts
const { record } = await nb.collection("users").signInWithPasskey({ cookie: true });
```

The device lists the user's passkeys for your site, so there is no email to
type. To offer them in the browser's autofill instead, give the email input
`autocomplete="username webauthn"` and start a sign-in that waits when the
page loads:

```tsx
useEffect(() => {
  const controller = new AbortController();
  nb.collection("users")
    .signInWithPasskey({ autofill: true, cookie: true, signal: controller.signal })
    .then(() => router.push("/"))
    .catch(() => {});
  return () => controller.abort();
}, []);
```

It signs in existing accounts. A passkey that is no longer on the account
answers `passkey_not_found`, and the client asks the browser to stop
offering it, where browsers support that.

## Manage passkeys

```ts
const passkeys = await users.listPasskeys(record.id);
await users.renamePasskey(record.id, passkeys[0].id, "Phone");
await users.deletePasskey(record.id, passkeys[0].id, { password });
```

Removing one takes the same proof as adding one, and the owner is emailed.
Keep another way to sign in, such as a password, an email code or a
provider, so a user who loses their device can still get in.

## With multi-factor sign-in

A passkey is the `passkey` method. When the device checked the user, by
fingerprint, face or PIN, it is two factors in one, the device and its
unlock, and signs in without a second step, even when the account has an
authenticator app. A security key that does not check the user is a first
step, and the [second step](/docs/guides/auth/mfa) follows. A passkey is
also a second step, after a password for example:

```ts
await users.signInWithPasskey({ mfaId: error.mfa.mfaId });
```

The emails are the `passkeyAdded` and `passkeyRemoved` kinds, which
[templates](/docs/guides/auth/email#custom-templates) can replace.
