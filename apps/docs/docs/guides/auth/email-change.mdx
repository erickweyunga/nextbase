# Email change

A signed-in user changes their email by confirming a link sent to the new
address. When their current email is verified, its inbox approves the change
first. It needs [email sending](/docs/guides/auth/email).

## Send the link

```ts
await nb.collection("users").requestEmailChange("ann@new.example.com");
```

The user must be signed in. Whether another account already uses the new
address is checked only on confirming, so the request reveals nothing.

## Approve it from the current inbox

When the current email is verified, the first link goes there instead, to
`/approve-email-change?token=...` in your app. So someone who took over a
session cannot move the account to their own inbox. That page approves it,
and the new address then gets its link:

```ts
await nb.collection("users").approveEmailChange(token);
```

The approval link works once, for the address it names, and like the other
links for 30 minutes by default (the collection's `emailChange` token
duration). When the current email is not verified, there is no approval, and
the new address gets its link at once.

## Confirm it

The email links to `/confirm-email-change?token=...` in your app. That page
asks for the current password and confirms the change:

```ts title="app/confirm-email-change/actions.ts"
"use server";
import { redirect } from "next/navigation";
import { nb } from "@/lib/nextbase";

export async function confirmEmailChange(form: FormData) {
  const client = await nb();
  await client
    .collection("users")
    .confirmEmailChange(String(form.get("token")), String(form.get("password")));
  redirect("/sign-in");
}
```

After the change:

- the link cannot be used again, even by requests sent at the same time,
- with an [authenticator app](/docs/guides/auth/mfa), confirming also needs
  `{ mfaCode }`, a code from it or a recovery code,
- the new email counts as verified,
- every session of the account ends, so the user signs in again,
- the old address gets an email saying the email changed.

Only superusers, or callers matching the collection's `manageRule`, can change
an email directly by updating the record.
