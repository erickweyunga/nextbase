NextBase rate limits HTTP requests, on by default: sign-ins, sign-ups, refreshes and email and phone flows 2 every 3 seconds, record creates 20 every 5 seconds, batches 3 a second, and every other route 300 every 10 seconds. Signed-in callers are counted per account, guests per IP from `clientIp` (IPv6 by its /56); guests whose IP is unknown are not limited, with one warning per instance, and requests with an invalid token count as a guest's. Each write of a batch counts as if sent on its own, and a batch with any write over its limit is refused whole. Creates in auth collections count as sign-ups, unless a rule limits creates in that collection. Counts are fixed windows kept in an unlogged table, `nextbase._rate_limits`, one upsert per request before any transaction, so limits hold across instances and parallel requests cannot all pass; a count over its limit is not rewritten, and each instance answers further refusals in its window from memory. A refused request gets a 429 with `Retry-After`, `RateLimit-Policy` and `RateLimit` headers, and is logged at warn; a refused OAuth2 sign-in start redirects back with `error=too_many_requests` instead. The new `rateLimits` option replaces the rules, each a label (`users:auth`, `*:create`, `POST /batch`, `/path` or `/prefix/`, but no path below one collection), an optional audience, `max` and `window`, sets `excludedIps` (IPs or CIDR ranges), or turns limits off with `false`. Superusers, `nextbase.client()` requests, health checks and the admin page are never limited. The limit on failed sign-ins per account still applies.
