Sign-ins can take a second step. Each auth collection, `_superusers` included, has an `mfa` setting: `enabled`, a `rule` saying which accounts must take it (`null` for accounts with an authenticator app, `""` for all, or a filter), and a `duration` from 60 to 3600 seconds. A first step that needs a second answers `401` with an `mfaId` and the `methods` left, and starts no session. The second step is an authenticator app code (TOTP), a recovery code, a code sent to the verified email or phone, a password, or a linked OAuth2 provider. It is never the first method again, only the app or a recovery code once an app is set up, and only the app or a recovery code for superusers, who add their first app with `nextbase superuser mfa-setup <email>`. A password reset by email or text does not pair with a code sent to the same place for 24 hours, and the owner is told; a password made up at an OAuth2 or phone sign-up is never a step. After an OAuth2 sign-in, the `mfaId` is kept in an `HttpOnly` cookie, the app's redirect gets `mfa=required`, and `GET /collections/{c}/mfa` reads the methods. Records manage their app at `records/{id}/mfa`, `totp`, `totp/confirm` and `recovery-codes`; setting one up always needs the current password, and its secret is encrypted with the new `secretKey` option (`NEXTBASE_SECRET_KEY`). Superusers clear another record's app with `DELETE records/{id}/mfa`, and `nextbase superuser mfa-reset <email>` removes a superuser's. Once an app is set up, removing it, regenerating recovery codes, confirming an email change and changing the password with `oldPassword` need a code as `mfaCode`. Setting or changing the phone and linking or unlinking a provider now need the current password, plus `mfaCode` with an app; a link starts with `POST /collections/{c}/link-oauth2/{provider}` instead of `?link=true`. A verified email's inbox must approve an email change, at `/approve-email-change`, before the new address gets its link. Sessions record how they signed in as `methods`, returned in auth responses and session lists and read by rules as `@request.mfa`; impersonation sessions record `impersonation` and skip the second step. A sign-up that has no second step to take yet answers `202` with `{ "mfa": "verify" }`. The SDK keeps its auth store on a `401` that asks for a second step, and adds `isMfaRequired()`, `signInWithTotp()`, `signInWithRecoveryCode()`, `requestEmailCode()`, `signInWithEmailCode()`, `requestMfaPhoneCode()`, `signInWithMfaPhoneCode()`, `getPendingMfa()`, `approveEmailChange()`, `oauth2LinkUrl()`, an `mfaId` option on `signInWithPassword()` and `signInWithOAuth2()`, and `getMfa()`, `startTotp()`, `confirmTotp()`, `removeTotp()`, `regenerateRecoveryCodes()` and `clearMfa()`.
