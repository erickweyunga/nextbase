Sign-ins can take a second step. Each auth collection, `_superusers` included, has an `mfa` setting: `enabled`, a `rule` saying which accounts must take it (`null` for accounts with an authenticator app, `""` for all, or a filter), and a `duration` from 60 to 3600 seconds. A first step that needs a second answers `401` with an `mfaId` and the `methods` left, and starts no session; the second step is an authenticator app code (TOTP), a recovery code, a code sent to the verified email or phone, a password, or a linked OAuth2 provider, never the first method again, and only the app or a recovery code once an app is set up. After an OAuth2 sign-in, the `mfaId` is kept in an `HttpOnly` cookie. Records manage their app at `records/{id}/mfa`, `totp`, `totp/confirm` and `recovery-codes`; the app's secret is encrypted with the new `secretKey` option (`NEXTBASE_SECRET_KEY`). Once an app is set up, removing it, regenerating recovery codes, confirming an email change and changing the password with `oldPassword` need a code (`mfaCode`). Sessions record how they signed in as `methods`, returned in auth responses and session lists and read by rules as `@request.auth.mfa`; impersonation sessions record `impersonation` and skip the second step. `nextbase superuser mfa-reset <email>` removes a superuser's app. A user field named `mfa` in an auth collection, which `@request.auth.mfa` now names, is renamed to `user_mfa`, with the rules that use it. The SDK keeps its auth store on a `401` that asks for a second step, and adds `isMfaRequired()`, `signInWithTotp()`, `signInWithRecoveryCode()`, `requestEmailCode()`, `signInWithEmailCode()`, an `mfaId` option on the other sign-ins, and `getMfa()`, `startTotp()`, `confirmTotp()`, `removeTotp()` and `regenerateRecoveryCodes()`.
